# v1.2 易用性改造实施计划

## Goal

把 v1.1 的“网页可配置”继续推进到“好接入、好值守、好交接”：批量导入主机、告警静默/维护窗口/聚合/恢复通知、主机分组与概览筛选、Windows 单实例/端口回退/托盘/网页日志。最终重新产出 Windows 绿色包并真实启动验证。

## Architecture

- 配置仍是“YAML/.env 作为种子 + SQLite `app_settings`/`app_secrets` 覆盖”；新增主机元数据字段与运行时开关，保存后 `MonitorService.apply_config()` 热应用。
- `host_import.py` 保持纯函数：只接收文本、返回候选/错误/警告，由 `SettingsService.import_hosts` 负责写库。
- 告警静默存 SQLite `alert_silences`，`AlertEngine` 每轮从 `storage` 读取；静默命中不写 alerts、不通知，创建静默时把 scope 内 open alerts 标 resolved。
- 同主机同轮告警在 `AlertEngine.process` 内聚合，`Notifier.dispatch_batch` 负责桌面/邮件/Webhook 各发一条；恢复事件走 `recovery_event` + 同一引擎。
- 运行时启动顺序：单实例锁 → 配置 → 端口选择 → scheduler → waitress → 写 runtime.json → 可选托盘/打开浏览器。

## Tech Stack

Python 3.11+；Flask 3 + waitress；Jinja2 + 原生 JS（无构建链）；SQLite；paramiko；pytest；PyInstaller `--onedir`；新增 `pystray>=0.19.5`、`Pillow>=10.0`（托盘，失败可降级）。

## Spec

设计文档：`docs/plans/2026-11-06-v1.2-usability-design.md`（已确认 2026-11-06）。本计划中的所有接口/字段必须以该设计为准。

## Global Constraints

- 保持 v1.1 的安全不变量：秘密只进 `app_secrets`（DPAPI），公开 API 永不回显秘密；CSRF 覆盖所有写请求；`/setup` 只允许 loopback；登录限速不降低。
- 保持 Docker/Linux 可启动：DPAPI 不可用时设置页只读，不能因新功能阻断启动。
- 不引入前端构建链、不引入数据库迁移框架；所有新表用 `CREATE TABLE IF NOT EXISTS`。
- 修改现有行为必须补回归测试；每个任务结束运行 `python -m pytest -q`（cwd `servermonitor-main/servermonitor-main`），只允许 0 failed。
- 保存后热应用失败不能破坏原有服务；异常必须被记录且主轮询继续。
- 不把 SSH 密码写入 YAML/CSV/日志；导入只处理 key 认证。

## Review Focus

1. 静默语义：创建静默是否真正把 scope 内 open alerts 标 resolved；静默结束后条件仍在是否重新告警；全局/分组/单机匹配是否正确。
2. 聚合与恢复：`dispatch_batch` 是否每通道只发一条；恢复事件是否只发一次、可关闭、不会无限循环。
3. 导入安全：服务端只解析上传文本；SSH config 的 ProxyJump/ProxyCommand 是否被明确拒绝；CSV 编码/分隔符/重复名处理。
4. 启动健壮性：单实例锁、端口回退、托盘失败降级、server.close 退出路径；不能因为托盘依赖缺失导致服务起不来。
5. 兼容性：旧 YAML/旧 `hosts` entry 无新字段时默认值正确；Docker/Linux 无 DPAPI 时不崩溃；v1.1 的测试全部通过。

**接口**
```python
@dataclass(frozen=True)
class HostCandidate:
    name: str
    host: str
    port: int = 22
    username: str = ""
    auth_type: str = "key"
    key_path: str | None = None
    tags: tuple[str, ...] = ()
    disk_mounts: tuple[str, ...] = ("/", "/data")
    group: str = "未分组"
    owner: str = ""
    location: str = ""
    notes: str = ""
    warnings: tuple[str, ...] = ()
    valid: bool = True
    error: str | None = None

@dataclass(frozen=True)
class ParseResult:
    candidates: list[HostCandidate]
    errors: list[dict]
    warnings: list[str]
```
- `parse_ssh_config(text, *, home: Path | None = None) -> ParseResult`
  - 支持 `Host`（可多别名）、`HostName`、`User`、`Port`、`IdentityFile`；`~` 展开；相对 IdentityFile 相对 `~/.ssh`。
  - `ProxyJump`/`ProxyCommand`：候选 `valid=False`、`error="需要代理跳转，工具暂不支持"`、warning 同理；不要静默导入。
  - `Match`/通配符 Host（`*`/`?`/`!`）/`Include`：跳过并给 warning；`Host *` 不生成候选。
  - 同一 Host 多别名：每个别名生成一个候选（共享属性）。
  - `key_path` 不存在只 warning（允许换机后补）。
- `parse_csv(text) -> ParseResult`
  - 必需列 `name,host`，可选 `username,port,auth_type,key_path,tags,disk_mounts,group,owner,location,notes`；支持中文表头同义词（名称/地址/端口/用户名/私钥/认证/标签/磁盘目录/分组/负责人/位置/备注）。
  - 编码优先 UTF-8-sig，失败 GB18030；分隔符逗号或制表符（`csv.Sniffer`，失败回退逗号）。
  - tags/disk_mounts 用 `,` 或 `;` 分割；`disk_mounts` 空则默认 `("/", "/data")`。
  - 单行错误进 `errors`，不伪造数据。
- `parse_yaml(text) -> ParseResult`：`hosts:` 列表或根列表；字段同 CSV；非法 YAML 返回 `errors`。

**Step 1**：先写测试（ssh 多别名、ProxyJump、通配符、CSV 中文表头/BOM、YAML、非法行）。确认失败。
**Step 2**：实现纯函数，不读写文件系统（`home` 仅用于路径展开）。

**实现**
- `SilenceRegistry(db_path, *, clock=None)`：`active_for(host_name, groups, now) -> dict | None`；每次调用读 `storage.list_silences(active_only=True, now=now)`，按 `all`→`group`→`host` 匹配，返回第一条命中。
- `AlertEngine.__init__(..., silence_checker=None)`；`process` 内对每个事件先查静默，命中 `LOGGER.info("alert suppressed by silence ...")` 并跳过（不 persist、不 dispatch）。
- `process` 分组：`aggregate_by_host=True` 时按 host 聚合同轮通过 `_should_skip` 的事件；单条仍 `dispatch`；多条 `dispatch_batch(events, config)`。每个事件都要 `_persist`，accepted channels 写回每条对应行。
- `Notifier.dispatch_batch(events, config) -> list[str]`：单条转 `dispatch`；多条构造“主机 + N 项告警”的合并标题/正文，桌面/邮件/Webhook 各发一次；某通道失败不影响其他通道。
- `resolve(host, category, *, notify=True)` / `resolve_missing(..., notify=True)`：关闭 open 行后，每个 `(host,category)` 生成一条 `recovery_event`，若 `notify_on_recovery` 且未被静默，则调用 `process([...])`，返回恢复事件列表。已无 open 行时不生成。
- 保持 `_should_skip` 现有 ack/error_increase/cooldown 语义；恢复事件 fingerprint `recovery:<host>:<category>`，下一轮 `resolve_missing` 自然 resolved。
