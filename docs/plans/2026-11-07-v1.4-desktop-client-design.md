# v1.4 桌面客户端化、PVS 风格 UI、主机连接向导与内置 SSH 终端设计

- 状态：已确认（2026-11-07 用户批准）
- 日期：2026-11-07
- 基线：v1.3.1（Electron 壳 + Python sidecar，绿色包）

## 1. 目标

在保留现有监控、告警、报告、磁盘健康、网页设置能力的前提下，把工具从“内嵌网页的窗口”升级为真正的 Windows 桌面客户端形态，并补齐日常运维最常用的两个动作：

1. **桌面客户端化**：无边框窗口、自定义标题栏、原生菜单与托盘、桌面式左侧导航与弹窗布局，不再呈现浏览器网页观感。
2. **全站 UI 改版**：参考用户提供的 PVS 控制台截图，采用左侧导航、顶部状态栏、卡片式统计、圆角表格、浅色留白与弹窗式表单，全站统一。
3. **添加主机连接向导**：新增主机时按步骤填写连接信息、测试连接、自动识别主机信息、选择监控项并保存，不再手工拼配置。
4. **内置多标签 SSH 终端**：在本机客户端内直接打开服务器交互式 shell，支持多台主机多标签并行，仅记录会话元数据审计。

## 2. 已确认需求

- 客户端形态采用 **Electron 桌面化**：保留现有技术栈与全部功能，做无边框/自定义标题栏/原生菜单托盘/桌面式布局。
- **不保留局域网浏览器访问**：后端只监听本机回环地址，纯单机客户端；SSH 终端自然仅本机可用。
- 新增主机使用三步连接向导：连接信息 → 自动识别并选择监控项 → 保存。
- 自动识别结果允许修改后保存。
- SSH 终端支持多标签，同时打开多台服务器；仅本机 Electron 窗口可用。
- 终端审计只记录会话元数据（谁、何时、哪台主机、来源 IP、开始/结束），不保存具体命令与输出。
- 全站 UI 统一改版，参考 PVS 的视觉结构，不引入外部 CDN。

## 3. 方案选择

### 3.1 客户端形态

采用 Electron 无边框窗口 + 自定义标题栏：

- `BrowserWindow` 使用 `frame: false`，由页面顶部自绘标题栏（应用图标、标题、最小化/最大化/关闭按钮），通过 preload 暴露的窗口控制 IPC 操作。
- 保留 Electron 原生菜单（文件/查看/帮助）与系统托盘（显示主窗口、复制看板地址、打开日志目录、退出）。
- 禁用页面右键菜单、文本选择（终端与输入框除外）、浏览器缩放，避免网页感。
- 关闭窗口仍然隐藏到托盘；托盘退出才真正结束 Python sidecar。

不选择 PySide6/Qt 重写：全部页面、表格、图表、设置表单与 SSH 终端都需重做，周期与回归风险远高于收益。

### 3.2 纯单机客户端

- 新安装的 `config/config.yaml` 种子把 `dashboard.host` 写成 `127.0.0.1`；Docker/浏览器部署仍可自行配 `0.0.0.0`，不改变其兼容性。
- **桌面模式**（`SERVERMONITOR_DESKTOP=1`）下，后端启动时把监听地址强制归一为 `127.0.0.1` 并记录警告，不因配置成非回环而退出；同时 Electron 的 `validateDashboardHost` 只接受回环地址。
- 打包不再附带 `允许局域网访问.ps1`，README/使用说明删除“局域网访问”章节。
- Web 前端仍由本地 sidecar 提供，仅 Electron 窗口加载；用户无需感知浏览器。

### 3.3 UI 方案

- 沿用 Jinja2 模板 + 原生 CSS/JS，不引入前端框架与构建链。
- 新增统一布局：左侧 220px 导航栏（概览/主机/磁盘健康/告警/终端/设置），顶部标题栏与状态区，内容区最大宽度自适应。
- `/login`、`/setup` 改为居中的客户端式卡片，而不是整页浏览器表单；首次 setup 仍保留安全门槛。
- 图标使用内联 SVG sprite，字体使用系统字体（Microsoft YaHei / Segoe UI），不依赖网络。
- 色彩参考 PVS：浅灰白背景、白色卡片、蓝紫主色、圆角 12–16px、轻阴影；状态色沿用现有绿/橙/红语义。
- 表格改为圆角卡片内表格，行悬停高亮；表单改为桌面式弹窗/抽屉。

### 3.4 SSH 终端方案

选择 **xterm.js + SSE/POST**，不引入 WebSocket 服务器改造：

- 前端使用 vendored `@xterm/xterm` 与 `@xterm/addon-fit`（离线静态文件，附 LICENSE）。
- 后端为每个终端会话维护一个 Paramiko `invoke_shell()` 通道与输出队列。
- 输出通过 `GET /api/ssh/sessions/<id>/stream` 的 `text/event-stream` 推送（Base64 分片，避免二进制/编码问题）。
- 输入通过 `POST /api/ssh/sessions/<id>/input` 提交；窗口尺寸通过 `POST .../resize` 同步 PTY。
- 关闭通过 `DELETE /api/ssh/sessions/<id>`；页面关闭/断线时后端在空闲超时后回收。
- 理由：Waitress 不支持 WebSocket 升级；SSE + POST 在现有 WSGI 栈内可稳定工作，且本地回环延迟足够低。
- **Waitress 线程池**：SSE 长连接会长期占用工作线程，`_build_server` 必须显式设置 `threads=32`、`channel_timeout=3600`（并确保 `server.close()` 能在 Electron 的 7 秒停止窗口内结束）；否则 3–4 个终端标签就会耗尽线程、拖死看板 API。每个会话输出队列有上限（如 1MB，超限丢最旧块），SSE 生成器在客户端断开时立即退出。

## 4. 架构与模块

### 4.1 后端新增模块

- `servermanage/ssh_terminal.py`
  - `SshTerminalManager`：创建/获取/关闭会话，线程安全字典，最大并发会话数（默认 8），空闲超时（默认 30 分钟）。
  - `SshTerminalSession`：封装 Paramiko client、`invoke_shell(term="xterm-256color", width, height)`、读线程、输出队列、`send_input(bytes)`、`resize(cols, rows)`、`close()`。
  - 仅接受回环来源的连接（路由层校验）；终端 API 额外要求 `SERVERMONITOR_DESKTOP=1`，浏览器模式即便本地访问也返回 403。
  - `SSHClientWrapper` 增加公开的 `open_shell(term="xterm-256color", width, height)`（复用 `_get_client()` 的连接逻辑，设置 transport keepalive/settimeout，返回 `paramiko.Channel`）；每个终端会话独占一个 `SSHClientWrapper`/client，关闭会话时一并关闭；终端模块不得直接访问私有 `_client`。
- `servermanage/host_probe.py`
  - `probe_host(candidate, *, ssh_factory, timeout) -> ProbeResult`：测试 SSH 登录并采集主机名、系统版本、内核、CPU 核数、内存、磁盘挂载、storcli/sudo 可用性。
  - `ProbeResult`：`ok/status/message/hostname/os_release/kernel/cpu_cores/memory_mb/mounts/storcli_available/storcli_path/sudo_available/warnings`。
- `servermanage/ssh_audit.py`
  - `record_session_start/record_session_end/list_sessions/purge_old_sessions`。

### 4.2 数据表

新增 `ssh_audit_sessions`（`username` 为看板管理员账号，`server_username` 为 SSH 登录账号；纯本机模式下 `remote_addr` 恒为 `127.0.0.1`，仅用于证明来自本地，不具外部定位意义）：

```sql
CREATE TABLE IF NOT EXISTS ssh_audit_sessions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  host_name TEXT NOT NULL,
  username TEXT NOT NULL,
  server_username TEXT,
  remote_addr TEXT NOT NULL,
  started_at TEXT NOT NULL,
  ended_at TEXT,
  status TEXT NOT NULL DEFAULT 'active',
  error TEXT
);
CREATE INDEX IF NOT EXISTS idx_ssh_audit_started_at ON ssh_audit_sessions(started_at);
```

`purge_old_data` 同步清理超过保留期的终端审计行。

### 4.3 API

新增（全部要求已登录、CSRF；SSE GET 只读）：

- `POST /api/settings/hosts/probe`：连接测试 + 自动识别。请求体包含 host/port/username/auth_type/password/private_key/key_path/passphrase（与 `_host_config_from_payload`/`upsert_host` 现有 `private_key` 字段名一致）；**绝不落库、不写日志**。返回 `ProbeResult`。
- `POST /api/ssh/sessions`：`{host_name, cols, rows}` → `{session_id}`。
- `GET /api/ssh/sessions/<id>/stream`：SSE 输出；`data: {"b64":"..."}` 分片；定期 `: keep-alive`。
- `POST /api/ssh/sessions/<id>/input`：`{b64}`。
- `POST /api/ssh/sessions/<id>/resize`：`{cols, rows}`。
- `DELETE /api/ssh/sessions/<id>`：关闭。

终端端点额外校验 `request.remote_addr` 为 `127.0.0.1`/`::1`，否则 403；非桌面/浏览器本机同样允许（本地操作者）。

### 4.4 页面

- `/` 概览：四张统计卡（主机总数/在线/离线/活动告警） + 主机表格 + 筛选。
- `/host/<name>`：主机详情，增加“打开终端”按钮；保留指标、磁盘阵列、登录用户。
- `/alerts`：告警列表与静默入口（沿用现有功能）。
- `/terminal`：多标签终端页；顶部标签栏（每标签主机名 + 关闭按钮），主体 xterm 容器，底部连接状态；左侧可选主机下拉。
- `/settings`：六分区设置页改为桌面式左二级菜单 + 表单。

## 5. 主机连接向导

### 5.1 入口

- 概览页右上角“添加主机”按钮；设置页主机区同样提供。
- 点击打开三步弹窗（也可作为独立 `/hosts/new` 页面，桌面窗口内更接近客户端弹窗）。

### 5.2 步骤 1：连接信息

字段：名称（可空，自动建议）、地址、端口（22）、用户名、认证方式（密码/私钥）、密码或私钥文件（上传内容 / 粘贴文本）、私钥口令（可选）。浏览器沙箱不能读取本机文件路径，因此向导只接受“上传私钥文件内容”或“粘贴私钥文本”；若未来需要“本机路径”，必须经 Electron preload 的专门 IPC 对话框实现（v1.4 不做）。

操作：
- “测试连接”调用 `POST /api/settings/hosts/probe`。
- 成功后保存候选连接信息到前端状态（秘密仅存在内存），进入步骤 2。
- 失败显示明确错误（认证失败、超时、拒绝连接、主机密钥问题），允许修改重试。

### 5.3 步骤 2：自动识别与监控项

显示并允许编辑：

- 主机名（默认探测值；作为建议名称，重名自动加 `-2`）。
- 系统版本、内核、CPU 核数、内存总量。
- 磁盘挂载点列表：建议 `/` 与 `/data`（存在时默认勾选），可增删；每个挂载点是否启用容量监控。
- 磁盘健康：检测 storcli 是否存在；若可用则默认启用，否则提示“未检测到 storcli，磁盘健康将不可用”。
- sudo 可用性：显示 `sudo -n` 是否可用；不可用时说明磁盘健康可能需要配置 sudoers。
- 分组、负责人、位置、备注。

### 5.4 步骤 3：确认保存

显示摘要（地址、用户名、认证方式、监控项、分组），点击“保存主机”。

保存复用现有 `PUT /api/settings/hosts/<name>` 语义：先写入主机秘密，再写主机记录；失败不破坏旧记录。保存成功后关闭弹窗、刷新概览。

## 6. 磁盘容量监控

- 每台主机可配置多个 `disk_mounts`（默认 `["/", "/data"]`）。
- 容量只针对实际存在的挂载点计算阈值；缺失挂载点页面显示“未挂载/异常”，不进入告警。
- 概览磁盘列显示最大值及异常挂载数量；主机详情展示每个挂载点的使用率与状态。
- 向导步骤 2 根据探测到的 `df -hP` 自动建议挂载点，允许增删。

## 7. 当前登录用户

- 现有 `who` 采集已包含用户名/终端/登录时间/来源 IP。
- 概览列显示去重用户数（悬浮显示会话数）；主机详情列出全部会话。
- 只展示，不告警。

## 8. 桌面客户端细节

### 8.1 窗口与菜单

- `BrowserWindow`：`frame:false`、`width 1360`、`height 860`、`minWidth 1100`、`minHeight 700`，背景色 `#f5f6fa`。
- 自绘标题栏高度 44px：左侧应用图标 + “服务器轮询监测工具”，右侧最小化/最大化/关闭；`-webkit-app-region: drag`，按钮区 `no-drag`。
- 原生菜单：文件（打开配置目录/退出）、查看（刷新/开发者工具仅开发）、帮助（关于/日志目录）。
- preload 暴露 `desktopBridge.windowControls.minimize/toggleMaximize/close/isMaximized`（以及 `maximized` 变化事件）；renderer 只调用这些方法。主进程实现 `maximize/unmaximize` 切换、`maximize`/`unmaximize` 事件回传、标题栏双击最大化、按钮区 `-webkit-app-region: no-drag`、窗口为 null 时安全返回。
- 保留托盘菜单与“关闭到托盘”；若托盘创建失败，关闭窗口会直接退出（Windows 无其他入口），在日志中记录该降级。

### 8.2 纯本机绑定

- 打包默认 `dashboard.host: 127.0.0.1`。
- 后端启动时若 `SERVERMONITOR_DESKTOP=1` 且 host 非回环，记录警告并强制使用 `127.0.0.1`（Docker/headless 不受影响）。
- `main-helpers.validateDashboardHost` 在桌面模式只允许回环地址；配置文件 `dashboard.host` 仍允许 Docker 部署使用通配地址。
- 移除 `允许局域网访问.ps1` 的打包与文档；README 标注 v1.4 为单机客户端。

## 9. 安全

- 所有设置/终端写请求要求登录 + CSRF。
- 终端服务只接受回环来源；会话 ID 使用高熵随机串，禁止枚举。
- 主机密码、私钥、口令只保存在 DPAPI `app_secrets`；探测接口仅在内存中使用，不落库、不打印。
- 终端会话只记录元数据审计，不记录输入输出。
- 错误信息不回显秘密；日志过滤 password/key。
- 已知限制（非目标）：不做主机密钥指纹确认（沿用现有 AutoAddPolicy）。

## 10. 非目标

- 不做 SFTP/文件上传下载、端口转发、X11。
- 不做终端完整录屏/命令回放。
- 不做多用户/多角色，仍为单管理员模型。
- 不做移动端适配。
- 不保留局域网浏览器访问（v1.4 明确移除）。
