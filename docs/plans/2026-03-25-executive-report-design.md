# 领导版双模板日报设计

## 目标

在现有技术版日报基础上，新增一套面向领导的精简汇总邮件，并在同一次巡检后分别发送技术版和领导版两封邮件。

## 已确认需求

- 新增一套“领导版”邮件模板，与现有技术版并存。
- 同一轮采集只执行一次，不重复 SSH 采集。
- 技术版和领导版需要分别发送，可以配置不同收件人。
- 领导版邮件需要更加凝练、可视化、好看，适合领导快速扫读。
- 领导版需要同时覆盖：
  - 总体健康
  - 资源风险
  - 使用归属
- 领导版不应照搬技术版的大表格和全量明细。

## 方案选择

### 候选方案

1. 双模板 + 配置切换，一次只发一种。
2. 双模板 + 双邮件发送，同一次巡检后发两封。
3. 单邮件双区域，上半部分领导摘要，下半部分技术明细。

### 选型结论

采用方案 2。

原因：

- 最符合“新增一套领导版模板，和现有技术版并存”。
- 领导版可以独立优化为汇报视角，不受技术细节模板牵制。
- 技术版继续保留排障明细，不需要为了压缩信息而牺牲工程可读性。
- 采集仍只做一次，额外成本只在渲染和发送层，符合 DRY 和 KISS。

## 总体架构

### 运行流程

1. 主流程采集一次服务器数据。
2. 基于同一份 `DailyReport` 渲染技术版邮件。
3. 基于同一份 `DailyReport` 渲染领导版邮件。
4. 使用同一套 SMTP 发件配置，分别发送给两组收件人。

### 模块影响

- `servermanage/models.py`
  - 扩展报告配置模型，增加领导版配置。
- `servermanage/config.py`
  - 解析并校验领导版配置。
- `servermanage/report.py`
  - 支持渲染技术版与领导版两种风格。
- `servermanage/mailer.py`
  - 允许在复用同一 SMTP 配置的前提下为不同邮件覆盖收件人。
- `servermanage/main.py`
  - 主流程改成根据配置发送一封或两封邮件。

## 配置设计

技术版继续沿用当前配置：

- `smtp.to_addrs`
- `report.subject_prefix`

领导版新增建议配置：

```yaml
report:
  subject_prefix: "[Server Daily Report]"
  include_failed_hosts: true
  executive:
    enabled: true
    subject_prefix: "[Leader Summary]"
    to_addrs:
      - "leader@example.com"
```

规则：

- 未配置 `report.executive` 时，系统保持现有行为，只发技术版。
- `report.executive.enabled = true` 时，要求 `to_addrs` 非空。
- 领导版默认复用技术版的 `subject_prefix` 作为兜底，但建议显式配置。
- 领导版继续复用 `smtp` 的发件账号、密码和发件人地址，不新增第二套 SMTP。

## 领导版内容结构

领导版邮件采用 4 个核心区域：

### 1. 顶部总览卡

展示：

- 服务器总数
- 正常数
- 异常数
- 高风险数

### 2. 风险摘要

仅列出最值得关注的 3 到 5 个结论，例如：

- 采集失败主机
- CPU 高负载主机
- 内存占用高主机
- 磁盘使用率高主机
- GPU 高占用主机

### 3. 资源看板

每台服务器一行摘要，展示：

- 主机名
- CPU 使用率
- 内存使用率
- 最高磁盘使用率
- GPU 利用概况
- 状态标签

### 4. 使用归属摘要

每台服务器只展示最关键的归属线索：

- CPU 最高占用进程
- 内存最高占用进程
- GPU 主要使用者
- `Proc By User` 的前几项

重点是“谁在用”，而不是展开全量明细。

## 视觉设计

- 领导版采用商务汇报风格。
- 使用浅色背景、白色卡片、克制状态色。
- 可视化仅使用邮箱兼容的 HTML：
  - 数据卡
  - 状态标签
  - 简洁进度条
  - 紧凑表格
- 优先保证首屏信息密度和手机邮箱可读性。

## 技术版保持不变的边界

技术版继续保留：

- 全量磁盘明细
- Top CPU / Top Memory 进程表
- GPU 详情和 GPU 进程表
- 采集异常细节

领导版不应替代技术版，只是增加汇总视角。

## 发送策略

- 技术版发送失败：主流程返回失败。
- 领导版启用后发送失败：主流程同样返回失败，避免形成“部分成功但无人感知”的假象。
- 若领导版未启用，则不尝试渲染和发送。

## 测试设计

至少覆盖：

1. 配置解析能正确加载 `report.executive`。
2. 未配置领导版时，现有行为保持不变。
3. 启用领导版时，主流程会发送两封邮件。
4. 领导版邮件使用独立主题和独立收件人。
5. 领导版渲染结果包含总览卡、风险摘要、资源看板和归属摘要。
6. 领导版不应包含技术版的大型明细表结构。

## 非目标

当前版本不包含：

- 历史趋势图
- 图表图片服务
- 第二套 SMTP 配置
- Web 后台选择邮件版本
- 按角色动态裁剪字段权限
