# v1.2 易用性改造设计（主机接入 / 告警值班 / 分组筛选 / 常驻体验）

- 日期：2026-11-06
- 状态：已确认（2026-11-06 用户批准）
- 关联版本：1.1.0 → 1.2.0
- 参考：`docs/plans/2026-11-06-web-settings-monitoring-design.md`（1.1 网页在线配置）

## 一、目标与背景

1.1 已把“改 YAML/.env”变成网页在线配置，并交付 Windows 绿色包。当前实际痛点是**日常使用仍然偏手工**：

- 新增一批服务器要逐台填表单；已有 `~/.ssh/config` 的主机不能直接复用。
- 告警只有“桌面/邮件/Webhook + 冷却”，夜间维护、批量迁移、已知故障无法临时静默；同一台机器多个指标同时超阈值会连续弹窗。
- 主机没有分组/负责人，机器一多概览页不好筛选。
- 绿色包启动后只有黑窗口；用户容易重复双击、端口被占用时不知所措，也不知道日志在哪里。

v1.2 的目标：**把“能配”提升到“好值守、好交接”**，让实验室管理员可以批量接入主机、按值班场景控制告警、按组查看机器，并把常驻进程做得更像桌面工具。

## 二、范围

### 2.1 本版范围（v1.2）

1. **主机接入零手工**
   - 从本机 OpenSSH config 文件导入主机（浏览器选择文件，服务端解析预览）。
   - 从 CSV / YAML 批量导入主机。
   - 导入前预览、校验、标记重复；导入后可批量测试 SSH 连接。
   - 主机支持复制为新增（“复制一台”）。
2. **告警值班体验**
   - 单机 / 分组 / 全局静默（维护窗口）：起止时间、原因、创建人、可提前解除。
   - 同一轮同一主机的多个告警合并为一条通知（桌面/邮件/Webhook 各一条）。
   - 条件恢复时发送“恢复通知”（可关闭）。
3. **主机分组与概览筛选**
   - 主机新增 `group`、`owner`、`location`、`notes` 字段；沿用 `tags`。
   - 概览页支持按分组、状态、标签、关键字筛选；主机表显示分组/负责人/标签。
4. **常驻体验**
   - Windows 单实例：重复启动自动打开已有看板并退出。
   - 端口冲突自动顺延（可在监控设置关闭），并写入运行状态文件。
   - 启动自动打开浏览器（可关闭）。
   - 系统托盘：打开看板、打开日志目录、退出。
   - 网页查看最近日志（只读尾部，固定 `logs/servermonitor.log`）。
   - 日志继续使用 5MB × 5 的轮转文件，不新增外部队列。

### 2.2 非目标（v1.2 不做）

- 不做 smartctl / nvme-cli / mdadm / ZFS 的额外磁盘健康采集（v1.3）。
- 不做历史趋势图、容量预测、CSV/Excel 导出（v1.3）。
- 不做只读账号、HTTPS、配置导入导出、备份恢复（v1.3）。
- 不做多用户/RBAC；仍然是单管理员。
- 不自动把 SSH 私钥复制到其他电脑；导入只引用本机路径或要求粘贴私钥。
- 不把“缺失挂载点”接入告警（沿用 1.1：只在页面标记未挂载）。

### 2.3 平台约束

- Windows 11 是完整功能目标；Docker/Linux 继续保留原 YAML/.env + 只读设置页。
- 新功能在非 Windows 上：导入/分组/告警静默仍可用（只要设置可写）；托盘、单实例（命名互斥体）仅 Windows 完整生效，单实例在 Linux 用文件锁降级。
- 继续无前端构建链：Jinja2 + 原生 JS/CSS。
- 不新增数据库服务，所有状态进现有 SQLite。

## 三、关键设计决策

### 3.1 导入采用“上传文本/文件 → 预览 → 确认写入”

**决策**：浏览器用 `<input type="file">` 读取本机文件，作为文本 POST 给服务端解析；服务端不主动读取服务器文件系统上的任意路径。

**原因**：
- 工具运行在用户自己的 PC，`~/.ssh/config` 在浏览器所在机器，上传最直接；
- 服务端直接读路径会引入任意文件读取风险，且 LAN 访问时路径语义不清；
- 预览可避免解析错误直接写库。

支持格式：
- OpenSSH config（`.ssh/config`）
- CSV（UTF-8/UTF-8 BOM；支持 GBK 兜底）
- YAML（复用 PyYAML，结构为 `hosts:` 列表）

### 3.2 导入只处理“连接参数”，密码不进入文件

**决策**：导入候选只接受 `key` 认证（`IdentityFile` / `key_path`）；CSV/YAML 中的 `password` 列**不读取**。密码型主机在预览标为“需手动补密码”，不直接导入。

**原因**：密码写进 CSV 会留下明文；1.1 已建立“秘密只进 DPAPI”的约束。私钥路径可以导入，导入后仍可在编辑页粘贴私钥内容。

### 3.3 告警静默只阻止通知，不抹掉条件

**决策**：新增 `alert_silences` 表。告警引擎每轮先查静默；命中静默的事件**不发送、不写入 alerts 表**，但在应用日志记录 `suppressed by silence` 计数。静默结束后条件仍在，会按正常告警重新出现。

**创建静默时必须把该 scope 内现有的 open alerts（active/acknowledged）标记为 resolved（不发送恢复通知）**。否则旧 active 行仍在，静默结束后 `_should_skip` 会按 `cooldown_minutes`/`repeat_while_active` 继续抑制，导致“结束后重新告警”失效；这也是把静默当作一次显式“重置事件”的实现方式。DELETE 提前解除静默不撤销已 resolved 的历史行，条件仍存在时下一轮会新建告警。

**原因**：
- 避免维护窗口内反复写大量“已知”告警；
- 不改变告警表状态机，ack/resolve 语义不动；
- 维护窗口结束后无需清理“静默状态”的告警。

**范围**：
- `scope_type = host | group | all`，`scope` 分别为主机名/分组名/NULL。
- `starts_at` 默认当前时间，`ends_at` 必填；最长 30 天；可提前 DELETE 解除。
- 同一时间多条静默取交集（命中任意一条即静默）。

### 3.4 同主机同轮告警聚合为一条通知

**决策**：`AlertEngine.process` 先按主机分组；每个主机本轮通过去重/冷却的事件合并成一次 `dispatch_batch`。单条事件时保持原有文案；多条时标题为 `[主机 h] N 项告警`，正文逐条列出，严重度取最高。

**原因**：一台机器 CPU/内存/磁盘同时异常时，逐条弹窗会刷屏；按主机聚合保留信息量且不跨主机混淆。

**兼容**：继续保留 `Notifier.dispatch(event)` 单条接口；新增 `dispatch_batch(events, config)`，测试和旧调用不受影响。`AlertsConfig.aggregate_by_host=True` 默认开启，可在通知设置关闭。

### 3.5 恢复通知是“信息级事件”，可关闭

**决策**：`resolve_missing`/`resolve` 在关闭告警时生成 `recovery_event(host, category)`，交给同一个引擎按主机/类别去重发送，`AlertsConfig.notify_on_recovery=True` 默认开启。恢复事件本身也写入 alerts 表（severity=info），并在下一轮自然 resolved。

**原因**：值班人员需要知道“刚才那台机器恢复了”，否则只看到告警消失；同时允许不喜欢恢复消息的用户关闭。

### 3.6 主机分组/负责人是主机元数据，不是新的层级对象

**决策**：`HostConfig` 增加 `group`、`owner`、`location`、`notes` 四个自由文本字段，`group` 默认为“未分组”。不做独立的“组管理”表/接口；分组来自主机字段的去重集合。

**原因**：实验室规模 ≤ 几十台，自由文本足够；独立组对象会带来重命名/级联/空组等额外复杂度。

### 3.7 单实例用操作系统锁，端口顺延用显式探测

**决策**：
- Windows：`CreateMutexW` 命名互斥体 `Local\\ServerMonitorDashboard`；Linux：`fcntl.flock` 锁 `data/servermonitor.lock`。
- 启动时若已存在实例，读取 `data/runtime.json` 的 URL，打开浏览器后退出 0。
- 端口：先尝试 `dashboard.port`，被占用且 `app.auto_port_fallback=True` 时在 `port..port+20` 找空闲端口；成功后写 `data/runtime.json`，并日志/桌面通知实际端口。
- 关闭自动顺延则端口占用直接报错退出（保留原语义）。

**原因**：绿色包用户会重复双击；端口冲突是 Windows 上最常见启动失败原因。

### 3.8 系统托盘用 pystray + Pillow，失败可降级

**决策**：新增可选依赖 `pystray>=0.19.5`、`Pillow>=10.0`。托盘在独立线程启动；菜单：打开看板 / 打开日志目录 / 退出。托盘创建失败（无桌面、缺依赖）只记录警告，不影响主服务。
`app.tray_enabled=True` 默认，可在监控设置关闭。

**打包影响**：`packaging/servermonitor.spec` 移除 `PIL` 排除项，增加 `pystray`/`PIL` hiddenimports；包体预计增加 8–12MB，可接受。

### 3.9 日志查看只提供固定文件尾部

**决策**：`GET /api/logs?lines=N`（默认 200，最大 2000）读取 `logs/servermonitor.log` 尾部返回 `{path, lines}`；不接受路径参数。设置页“日志”卡片展示等宽文本，可刷新；托盘“打开日志目录”用系统文件管理器打开。

**原因**：排障时不用让用户找文件夹；固定路径避免任意文件读取。

## 四、数据模型

### 4.1 扩展 dataclass

```python
@dataclass(frozen=True)
class HostConfig:
    ...
    group: str = "未分组"
    owner: str = ""
    location: str = ""
    notes: str = ""

@dataclass(frozen=True)
class AppRuntimeConfig:
    ...
    auto_port_fallback: bool = True
    tray_enabled: bool = True
    open_browser_on_start: bool = True

@dataclass(frozen=True)
class AlertsConfig:
    ...
    aggregate_by_host: bool = True
    notify_on_recovery: bool = True
```

- `load_config_from_mapping` 读取 `servers[].group/owner/location/notes`，未知字段忽略。
- `app` 段读取三个布尔，缺省如上。
- `alerts` 段读取两个布尔，缺省如上。
- YAML 旧配置不需要改；有字段则生效，无字段用默认。

### 4.2 新表 `alert_silences`

```sql
CREATE TABLE IF NOT EXISTS alert_silences (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    scope_type TEXT NOT NULL,       -- host|group|all
    scope TEXT,                     -- host/group name; NULL for all
    reason TEXT NOT NULL,
    starts_at TEXT NOT NULL,        -- ISO-8601 UTC
    ends_at TEXT NOT NULL,          -- ISO-8601 UTC
    created_at TEXT NOT NULL,
    created_by TEXT                 -- admin username (display only)
);
CREATE INDEX IF NOT EXISTS idx_alert_silences_ends_at ON alert_silences(ends_at);
```

存储函数（`storage.py`）：
- `insert_silence(scope_type, scope, reason, starts_at, ends_at, created_by, db_path) -> int`
- `list_silences(db_path, *, active_only=False, now=None) -> list[dict]`
- `delete_silence(silence_id, db_path) -> bool`
- `purge_old_data` 增加删除 `ends_at < cutoff` 的静默记录。

### 4.3 主机条目

`hosts` 段每个 entry 增加 `group/owner/location/notes`；`_host_entry_from_config`、`_public_host_entry`、`_build_servers`、`upsert_host`、复制主机接口同步。

## 五、后端模块

### 5.1 新模块 `servermanage/host_import.py`（纯函数，无 I/O）

- `HostCandidate` dataclass：name/host/port/username/auth_type/key_path/tags/disk_mounts/group/owner/location/notes/warnings。
- `parse_ssh_config(text, *, home: Path | None = None) -> ParseResult`
  - 支持 `Host` 块、`HostName`、`User`、`Port`、`IdentityFile`。
  - `ProxyJump`/`ProxyCommand` 暂不支持：该主机仍生成候选，但标记 `warnings=["需要代理跳转，工具暂不支持"]` 且不导入，避免导入一个连不上的条目；`Match`、通配符 Host（`*`/`?`/`!`）跳过并 warning；`Include` 不展开给 warning。
  - `~` 展开；相对 IdentityFile 相对 `~/.ssh` 解析。
  - 同一 Host 多别名：每个别名生成候选（共享属性）。
- `parse_csv(text) -> ParseResult`
  - 必需列 `name,host`；可选 `username,port,auth_type,key_path,tags,disk_mounts,group,owner,location,notes`。
  - `tags/disk_mounts` 支持逗号或分号分隔。
  - 编码先 UTF-8-sig，失败 GB18030。
- `parse_yaml(text) -> ParseResult`
  - `hosts:` 列表；字段同 CSV。
- `ParseResult`：`candidates: list[HostCandidate]`、`errors: list[dict]`（line/message）、`warnings: list[str]`。
- 校验：name/host 非空；port 1–65535；auth_type 只允许 `key`；`key_path` 不存在只 warning（换机后可能重新指定）。

### 5.2 `SettingsService` 新方法

- `import_hosts(candidates: list[dict], *, overwrite: bool=False) -> dict`
  - 预校验全部名称/字段；重复名称且 `overwrite=False` 跳过并报告；逐台调用内部保存（复用 `upsert_host` 的校验与秘密逻辑），返回 `{created, updated, skipped, failed:[{name,error}]}`。
- `copy_host(source, new_name) -> AppConfig`：复制连接参数/分组/标签/disk_mounts 以及该主机的三个 SSH 秘密（密码/私钥/口令）——同一管理员在同一台 PC 上复制主机是常见需求，若不复制秘密会得到一个必坏的主机条目；复制发生在同一 DPAPI 用户作用域内，不扩大暴露面。目标名已存在则报错，源主机不存在则报错。
- `list_silences(active_only=False)` / `add_silence(...)` / `delete_silence(...)`。
- `host_groups() -> list[str]`（从当前主机去重，供前端筛选/静默下拉）。

### 5.3 告警层改动（`alerts.py`）

- 新增 `SilenceChecker` Protocol：`active_for(host_name: str, groups: list[str], now: datetime) -> dict | None`。
- `AlertEngine.__init__(..., silence_checker=None)`；`process` 第一层对每个事件查静默，命中则 `LOGGER.info("alert suppressed by silence ...")` 并跳过（不 persist、不 dispatch）。
- `process` 分组：`defaultdict(list)` by host；对每组先完成原有 `_should_skip` 和 `_persist`，再 `dispatch_batch(batch)`；把 accepted channels 记录到组内每一行。
- `Notifier.dispatch_batch(events, config) -> list[str]`：
  - 单条 → 原 `dispatch`；
  - 多条 → 按通道合并：desktop 一条、email 一封、webhook 一条；返回接受的通道名。
- `AlertEngine.resolve(host, category, *, notify=True) -> list[AlertEvent]` 和 `resolve_missing(..., notify=True)`：关闭行后生成每个 (host, category) 一条 `recovery_event`，若 `notify_on_recovery` 且未被静默，走 `process([...])`，返回恢复事件。
- `recovery_event` 文案保持，指纹 `recovery:<host>:<category>`。

**静默检查器**：`servermanage/alerts.py` 内实现 `SilenceRegistry` 从 `storage.list_silences(active_only=True)` 读取；`MonitorService` 每次 `apply_config` 重建（或每轮读取以反映网页新增，推荐每轮读取）。

### 5.4 `MonitorService` 接线

- `run_status_once` / `run_disk_once`：
  - 收集 `active_fingerprints` 后调用 `resolve_missing(..., notify=True)`。
  - 对 `offline` 恢复，`resolve("offline", notify=True)` 统一走恢复通知（移除旧的直接 `recovery_event` 拼接）。
- `apply_config` 重建 `AlertEngine` 时注入 `SilenceRegistry(db_path, now_fn=self._clock)`。
- 每轮前重新读取静默，避免网页新增要等重启。

### 5.5 运行时模块 `servermanage/runtime.py`

- `acquire_single_instance(lock_path: Path) -> InstanceLock`：返回对象，`release()`；Windows `CreateMutexW`/`WaitForSingleObject`，POSIX `fcntl.flock(LOCK_EX|LOCK_NB)`。
- `find_available_port(host: str, preferred: int, span: int=20) -> int`：socket 绑定测试。
- `write_runtime_state(path: Path, *, url: str, port: int) -> None`；`read_runtime_state(path) -> dict | None`。
- `open_browser(url)` 用 `webbrowser.open`，失败仅 warning。

### 5.6 托盘模块 `servermanage/tray.py`

- `tray_available() -> bool`（导入 pystray/PIL 成功且 Windows 有桌面）。
- `start_tray(*, url, log_dir, on_exit, enabled=True) -> TrayHandle`：daemon 线程；`TrayHandle.stop()`。
- 菜单：“打开看板”（webbrowser）、“打开日志目录”（`os.startfile`）、“退出”（调用 `on_exit` 后 `icon.stop()`）。
- 所有异常 catch 并记录，绝不影响主服务。

### 5.7 `app.py` 启动流程

```text
main():
  parse args
  configure_logging(logs)
  lock = acquire_single_instance(data/servermonitor.lock)
  if not acquired:
      state = read_runtime_state(); open_browser(state.url)
      return 0
  config, db_path, settings = load_runtime_with_settings(...)
  port = choose_port(config.dashboard.host, config.dashboard.port, config.app.auto_port_fallback)
  service = MonitorService(config,...); service.start()
  app = create_app(...)
  server = waitress.create_server(app, host, port)
  write_runtime_state(data/runtime.json, url=f"http://127.0.0.1:{port}", port=port)
  if config.app.open_browser_on_start: threading.Timer(0.8, open_browser, [url]).start()
  tray = start_tray(... on_exit=server.close ...)
  server.run()
```

- `waitress.create_server` 用于可从托盘关闭；`server.run()` 阻塞。
- 测试 `main` 用 monkeypatch 的 server/tray/browser，不真正阻塞。

### 5.8 新 API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/settings/hosts/import/preview` | `{format: ssh_config|csv|yaml, text}` → 候选+错误+警告，不落库 |
| POST | `/api/settings/hosts/import` | `{hosts:[...], overwrite: bool}` → 导入结果 |
| POST | `/api/settings/hosts/test-batch` | `{names:[...]}` 或 `{hosts:[...]}` → 每台 `{name, ok, latency_ms, error}`，并发≤4 |
| POST | `/api/settings/hosts/<name>/copy` | `{new_name}` → 复制主机（不含秘密） |
| GET/POST | `/api/settings/silences` | 列出/新增静默；POST 校验时间与 scope |
| DELETE | `/api/settings/silences/<id>` | 提前解除 |
| GET | `/api/logs?lines=200` | 返回日志尾部 |
| GET | `/api/runtime` | `{url, port, pid, started_at, tray}` |

所有写接口沿用 CSRF + `is_writable` 检查。`GET /api/overview` 每行新增 `group/owner/location/tags/silenced/silenced_until`；`/api/settings` 的 `hosts` 增四字段与 `groups`。

## 六、前端

### 6.1 设置页（settings.html / settings.js / style.css）

- 「主机与 SSH」卡片：
  - 新按钮：`从 SSH 配置导入`、`导入 CSV/YAML`、`批量测试选中`。

## 十、风险与取舍

| 风险 | 处理 |
|---|---|
| 导入 SSH config 的 `Include`/通配符/`%h` 变量不能完整展开 | 明确 warning，不静默猜测；用户可手工补 |
| 密码型主机无法从 CSV 导入 | 预览标红“需手动补密码”，避免明文落盘 |
| 静默不写告警历史 | 日志记录 suppressed 计数；如需审计后续再加 `silenced` 状态 |
| pystray/Pillow 增大包体/打包失败 | 懒加载+可关闭；spec 显式 hiddenimports，失败降级为无托盘 |
| 端口顺延导致书签失效 | 写 runtime.json + 托盘/浏览器使用实际端口 + 桌面通知；可在设置关闭顺延 |
| 单实例锁残留 | 操作系统锁随进程释放；启动时锁文件存在但拿不到锁不会误判 |

## 十一、需要用户确认的点（已给默认，允许直接按默认实施）

1. 系统托盘是否接受引入 pystray/Pillow，包体增加约 8–12MB？默认：接受。
2. 静默期间不写告警历史，只在日志记录，是否可以？默认：可以。
3. 导入只支持私钥认证，密码主机需手动补，是否接受？默认：接受。
4. 主机“分组”用自由文本而非独立组管理，是否接受？默认：接受。
