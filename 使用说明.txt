服务器轮询监测工具 v0.1.100（Windows 桌面客户端绿色包）使用说明
====================================================

一、解压与首次启动
1. 将整个压缩包解压到一个新文件夹（路径可含中文，不建议有特殊符号）。
   请不要只把 servermonitor.exe 单独拖出来，resources、config、data、logs 必须与它在一起。
2. 双击“启动.bat”（或直接双击 servermonitor.exe）启动桌面程序：会打开独立主窗口
   （无边框窗口，默认 1280×800，最小 1024×700），无需浏览器。首次启动会自动进入“初始化管理员”
   页面（/setup），请设置管理员用户名和密码（至少 8 位），以后用该账号登录。
3. 关闭主窗口（点右上角 X）不会退出程序，而是最小化到系统托盘继续监测。
   右键托盘图标可：显示主窗口 / 打开日志目录 / 复制看板地址 / 退出。
   要彻底退出，请使用托盘菜单的“退出”（会先优雅停止后台服务）。
   关闭或最小化窗口后会释放看板界面内存，从托盘重新打开约需 1～2 秒。
4. 停止：优先用托盘“退出”；也可双击“停止.bat”强制结束后台进程。

二、开机自启（可选）
右键“注册开机自启.ps1”→“使用 PowerShell 运行”（可重复执行）。脚本会创建登录时触发的
计划任务 ServerMonitorDashboard，直接执行 servermonitor.exe --start-hidden，只在托盘运行、
不弹主窗口；权限不足时回退到“启动”文件夹快捷方式。

三、网页在线设置
启动后在“设置”页面即可修改，无需手工编辑配置文件：
- 主机与 SSH：增删主机、分组/负责人/机房/备注、私钥/密码认证、每台磁盘容量监控目录；
  支持从 SSH config、CSV、YAML 批量导入并预览、批量连通性测试和复制主机。
- 服务检查：在主机编辑中可添加最多 20 个检查项（TCP 端口、HTTP/HTTPS、进程、systemd 服务），
  设置超时、期望状态码并测试；结果会显示在概览、主机详情和日报/周报。
- 告警规则：可为主机覆盖 CPU/内存/磁盘/GPU 阈值及连续异常周期数（1～10，默认 2）。
- 添加主机：点“连接向导”，先填写地址/端口/用户名/密码或私钥并测试，自动识别系统、CPU、内存、挂载点、sudo 与 storcli 后保存。
- SSH 终端：左侧“终端”可同时打开多台服务器标签；仅本机桌面客户端可用，只记录会话元数据，不记录命令与输出。
- 监控与存储：采集间隔、磁盘采集间隔、并发数、时区，以及状态曲线保留点数、磁盘健康保留天数/批次数、每日汇总、告警历史、SSH 审计的保留期。
- 容量预测：概览页根据最近 30 天每日汇总预测内存/磁盘/GPU 显存趋势，提前标记预计 7 天或 30 天内达到阈值的主机。
- 通知：桌面通知、邮件 SMTP、企业微信/钉钉/飞书/通用 Webhook；可聚合告警、恢复通知、告警静默。
- 报告：日报/周报启用状态、发送时间、周报星期。
- 主机列表：点击表头可按名称/地址/CPU/内存/磁盘/健康等排序；告警页支持“一键静默”1 小时/1 天/7 天。
- 磁盘健康：storcli 路径、温度阈值、各类错误告警开关。
- 服务器用户：左侧“服务器用户”查看各主机普通账号（UID ≥ 1000，系统账号不显示）、docker/sudo 组、
  家目录与 /data/<用户名> 的所有者、权限和占用；缺失账号会高亮，可“从基线移除”或等账号恢复。
  全部为只读检查，程序不会创建账号、改密码或改目录权限。每小时自动扫描一次，也可点“立即刷新”。
  若普通账号没有 sudo 权限，仅该账号的目录占用显示为不可用，不影响其它状态。
- 看板与安全：管理员用户名/密码（桌面客户端只监听本机 127.0.0.1，不再提供局域网访问）。

四、使用模式（管理员 / 用户）
本工具面向两类人：实验室管理员和实验室成员。设置页“监控与存储”卡片最下方的
“使用模式”可以二选一，切换后立即生效。

1. 管理员模式（默认）
   可以看到全部功能：概览、主机列表、磁盘健康、告警、服务器用户、终端、设置。

2. 用户模式（实验室成员）
   只需填写“我的服务器账号名”（例如 zhouyc），也就是你在服务器上的 Linux 账号。
   切换后：
   - 左侧导航只剩“我的服务器”和“设置”，不显示告警、终端、主机管理等功能；
   - “我的服务器”只列出你确实拥有该账号的服务器，按主机显示账号是否存在、
     docker/sudo 组、家目录与 /data 的所有者、权限和占用，异常会直接列出来；
   - 账号在服务器上不存在时，该主机会标为“缺失”，提醒联系管理员；
   - 用户模式下直接访问管理员页面会被带回“我的服务器”，管理员接口返回 403。
3. 需要时随时在设置页“切换回管理员模式”。
4. 说明：使用模式只是界面约束，不会改变服务器上的实际权限；真正的边界仍是
   SSH 账号、sudo 配置和目录权限。用户模式不提供任何写操作。

五、从 SSH 配置批量导入主机
1. 打开“设置 → 主机与 SSH”，点“从 SSH 配置读取”。
2. 程序自动读取当前 Windows 用户的 .ssh\config，列出所有 Host 候选及名称、地址、端口、用户、私钥。
3. 勾选需要监控的主机，可勾选“覆盖同名”，点导入；缺少私钥的主机会标记为待补凭据，导入后可手动补。
4. 导入或新增主机成功后会自动在后台采集一次状态和磁盘健康，页面显示采集进度，完成后自动刷新。

六、检查与自动更新
1. 打开“设置 → 看板与安全 → 软件更新”，点“检查更新”。
2. 有新版本时显示版本号和更新说明；点“下载更新”自动下载并校验 SHA256。
3. 校验通过后点“安装并重启”，程序会自动替换文件并重启；config\、data\、logs\ 会保留。
4. GitHub 发布仓库：zyc6665/lab-server-monitor（公开）；维护者打 tag 或手动触发 release-windows 工作流即可自动打包发布。

七、升级到新版本（保留数据）
1. 升级前先备份整个文件夹，至少备份 config\、data\、logs\ 三个目录。
2. 推荐把新版本解压到“新文件夹”，再把旧的 config\、data\、logs\ 复制覆盖进去；
   也可以保留原目录，只替换程序文件（servermonitor.exe、resources\ 等），
   切勿删除 data\servermonitor.db，否则会丢失主机、静默、历史采样等数据。
3. config\config.yaml 若已存在请保留，不要用模板覆盖；只有新电脑才用 config.yaml.example 新建。
4. 不要把包含 data 目录的整个文件夹发给别人；凭据使用本机 DPAPI 加密，换机需重新初始化。

八、安全说明（重要）
- SSH 私钥、SSH 密码、SMTP 密码、Webhook 地址等敏感信息使用 Windows 本机账户加密（DPAPI）
  保存，只在本机可解密；拷到另一台电脑会失效，需要在该电脑重新 /setup 并重新填写凭据。
- 每台电脑各自运行一套独立实例；同一文件夹只允许运行一个实例（单实例锁位于 data\electron）。
- 每台主机的 sudo 密码同样使用本机 DPAPI 加密保存，只写不回显；不会写入命令、日志或导出报告。

九、日志与排错
- 桌面主进程日志：logs\desktop.log；后台服务日志：logs\servermonitor.log（5MB × 5 份轮转）。
- 实际监听地址与端口：data\runtime.json；也可在托盘“复制看板地址”或设置页查看。
- 窗口打不开或提示“后台服务已停止”：查看 logs\desktop.log，确认端口未被占用；
  用托盘“退出”或“停止.bat”后重新启动。
- 忘记管理员密码：退出程序后删除 data\servermonitor.db 重新初始化（会丢失历史与主机配置，
  请先在“设置→主机与 SSH”记录）。

十、账号管理（默认关闭）
1. 设置 → 服务器用户监控 → 勾选“允许账号写操作”（总开关）。
2. 设置 → 主机 → 编辑目标主机 → 勾选“允许账号写操作”，并填写该主机的 sudo 密码。
3. 打开“服务器用户”页 → 选择主机 → 右上“新建账号”，或账号卡片上的
   “重置密码 / 加入 docker 组 / 建 data 目录”。
4. 点“预览执行计划”核对命令，再分别输入主机名与账号名，才能点“确认执行”。
5. 密码只走 SSH 标准输入，不写日志；计划 10 分钟过期；每次执行都会写审计记录。
